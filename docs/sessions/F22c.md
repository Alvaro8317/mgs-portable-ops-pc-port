# F22c — README, aviso legal e instalaciones limpias

- **Fecha**: 2026-11-03
- **Estado al cerrar**: 🟨 hecha en lo que se puede sin el usuario. Están el README del jugador
  (en inglés y en español) con el aviso legal, el smoke test con su herramienta de hashes y **dos
  instalaciones limpias en Linux** siguiendo solo el README (en esta máquina, a partir del tarball

### 2. Lo que se arregló al escribir el README

- **El navegador del launcher no llegaba a los saves de PPSSPP en Linux**: ocultaba las carpetas
  que empiezan con punto y no dejaba escribir una ruta, así que `~/.config/ppsspp/PSP/SAVEDATA`
  quedaba fuera. Ahora:
  - tiene un campo con la ruta (se escribe y Enter o Go);
  - una casilla **Show hidden folders** (`list_directory(…, show_hidden)`);
  - al importar o exportar saves, un botón **PPSSPP saves** por cada carpeta `SAVEDATA` de PPSSPP
    que exista (`ppsspp_save_folders`: `Documents\PPSSPP` en Windows; `~/.config/ppsspp` y el
    Flatpak de PPSSPP en Linux);
  - `--browse-saves` abre ese navegador al arrancar, para capturarlo con `--screenshot`.
- **El Flatpak no podía exportar saves**: con `--filesystem=home:ro` no tenía dónde escribir fuera
  del sandbox. Ahora tiene `--filesystem=xdg-download` (Descargas, de lectura y escritura) y el
  README dice que se exporte ahí [?, sin probar en un Flatpak instalado].
- **La lista de paquetes de Linux**: SDL3 se compila desde el código y, sin los headers, se queda
  sin drivers. **Sin los de audio, el juego compila pero no tiene sonido** (solo `dummy` y `disk`);
  sin `libegl-dev`, no hay Wayland (queda X11). La lista del README se comprobó en el contenedor
  (ver la evidencia).
- **FFmpeg tenía una sola URL**: durante la instalación del contenedor, `ffmpeg.org` dejó de
  responder (desde el contenedor y desde el host, un rato después de haber servido el tarball a
  la instalación del host). Ahora `MPO_FFMPEG_MIRROR_URLS` agrega los distfiles de Gentoo, que
  sirven **el mismo tarball** (SHA-256 `de668509…` [V]). `ExternalProject` prueba las URLs en orden
  y comprueba el SHA-256 siempre.

### 3. La primera prueba del usuario en Windows (el ZIP del run `41676018980`)

- **El `install` se paró al configurar** [V por el usuario]: CMake no pudo compilar el programa de
  prueba, porque `clang.exe` decía `…\bin\clang-23: No such file or directory`.
- En llvm-mingw 20261020, `clang.exe` es un envoltorio de 13 KB que lanza `clang-23.exe` (95 KB,
  que a su vez usa las DLL de LLVM). El ZIP fijado sí trae `clang-23.exe` (listado aquí, con el
  SHA-256 correcto), y en la carpeta del usuario estaban todos los `clang*.exe` descomprimidos a
  la misma hora **menos ese**. Lo quitó el antivirus: **Avast**, según el usuario (Windows 11
  build 26200). Es un falso positivo (la release oficial, con su SHA-256 comprobado). La CI no
  tiene antivirus en tiempo real y por eso nunca falló allí.
- **El problema nuestro**: `setup.py toolchain` daba la carpeta por buena con solo el sello del
  SHA-256 ("already there"), así que volver a pulsar Install no lo arreglaba nunca. Ahora:
  - `_unpack` guarda la lista de los archivos del ZIP (`.mpo-files`) y cada `toolchain` comprueba
    que estén todos; si falta alguno, o la carpeta es de antes y no tiene la lista, la vuelve a
    bajar y a descomprimir;
  - si faltan archivos justo después de descomprimir, o `clang --version` no corre, el error lo
    dice con el camino a seguir (el historial de protección, una exclusión para
    `%LOCALAPPDATA%\mpo-pc-port` y volver a pulsar Install), y borra el sello para que el próximo
    Install lo rehaga;
  - los dos README (una sección "If your antivirus removes a file"), el `README.txt` del ZIP y el
    mensaje de error nombran a Avast, dicen que es un falso positivo y explican cómo restaurar el
    archivo y agregar la excepción en Avast y en Seguridad de Windows;
  - el launcher lo advierte en Windows antes de Install, con la carpeta que hay que exceptuar.

### 4. El smoke test manual (`docs/smoke-test.md`)

- La lista corta de `CLAUDE.md` §7: preparar una carpeta de prueba (con `XDG_DATA_HOME` y
  `XDG_CONFIG_HOME` en Linux, `--env` en el Flatpak, y `APPDATA` y `LOCALAPPDATA` en Windows) para
  no tocar nunca los saves reales, 14 pasos con lo que tiene que pasar en cada uno, y comprobar
  los saves al final.
- **`packaging/hash_saves.py`** (`snapshot` y `compare`): el SHA-256 de cada archivo de una carpeta
  y la comparación después; sale con 1 si algo se agregó, se borró o cambió. Una carpeta que no
  existe cuenta como vacía. En Windows corre con el Python del ZIP. Lo prueba
  `mpo_hash_saves_test`.

## Decisiones tomadas

- **El README del jugador en inglés y en español** (el usuario), con el mismo contenido.
- **El README no promete lo que no está probado**: dice que no hay release, que el recorrido
  completo sigue en curso y que el ZIP de Windows no se ha probado en el PC de un jugador. Hay que
  actualizar esa línea cuando cierren F21b y la prueba de Windows.
- **El smoke test es un documento y una herramienta, no un script que juegue**: los pasos que
  importan (el video con sonido, el mando, los diálogos) se miran a mano. La herramienta solo
  hace la parte que se puede equivocar a mano, los hashes.
- **El espejo de FFmpeg es de Gentoo** porque sirve el tarball de upstream sin cambios. Se probaron
  también los de FreeBSD (el certificado no coincide), Buildroot y BLFS (no tienen la 7.1.5).

## Pendiente y trampas encontradas

- **Trampa: la repetición depende de la hora local de los archivos del `ms0` grabado** [V].
  - Copiando `tramo3.input.ms0` con `cp -r` (sin conservar las fechas), la repetición se separa
    en el flip 1620 (132/135), con el `mpo_boot` limpio **y con el de F21**, y con un hash distinto
    en cada corrida. Con `cp -a` coincide entera.
  - En el contenedor (en UTC, el host está en UTC−5), aun con las fechas conservadas, se separa en
    el mismo flip. Con `TZ='<-05>5'` coincide entera.
  - El diálogo de saves muestra la fecha y la hora de modificación del save en la hora local.
  - Para F23+: que `--record-input` guarde las fechas y la zona horaria, o que `--replay-input`
    las fije. Mientras tanto, las grabaciones se copian con `cp -a` (o `tar`) y se repiten en la
    misma zona horaria.
- **`ffmpeg.org` puede caerse**: ya hay espejo para FFmpeg. Las otras descargas del build (SDL3,
  Dear ImGui y los archivos de PPSSPP) vienen de GitHub, con una sola URL cada una.
- **Sin probar**: el permiso de Descargas del Flatpak y el `--env` del smoke test en un Flatpak
  instalado (aquí no hay `flatpak`); el README en Windows.

- **Windows y el antivirus**: falta confirmar con el usuario que, con la exclusión (o sin ella, con
  el arreglo de `setup.py`), el `install` llega al final. Si Defender vuelve a quitar archivos
  generados por el build (las DLL de etapa, `mpo_boot.exe`), habrá que decirlo en el launcher
  antes de instalar.
